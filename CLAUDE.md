# CLAUDE.md / OpenCode Guide for TIAgent

## Overview
This repository contains **TIAgent**, a local Openness bridge for Siemens TIA Portal (V14 SP1 to V21).
It enables AI agents to create PLC Tag tables, Global/Instance Data Blocks, write Ladder (SimaticML XML) and SCL blocks, configure PROFINET hardware drives (e.g. SINAMICS V90, G120), and compile projects with 0 errors.

## Role Separation Rules
- **"Köprüsün" (Bridge Mode)**: The agent MUST NOT modify or inspect TIAgent C# code (`*.cs`, `*.xaml`). It only calls TIAgent HTTP API (`http://localhost:19520`) or writes JSON packages to `Packages/Inbox/` to interact with Siemens TIA Portal.
- **"Programcısın" (Developer Mode)**: The agent develops, edits, debugs, and compiles `TIAgentMCPServer.csproj`.

## Mandatory Company PLC Engineering Standards
Every PLC package generated by any agent must strictly adhere to the user's 5 engineering standards:

### 1. 10 Standard Global DB Architecture
All project variables must be distributed into these 10 standard Global DBs:
- `"TIMER"`: TON/TOF/TP instances (`TON_Piston_Ileri`, `TON_Bekleme`, `TON_Kacak`, etc.).
- `"ERROR"`: All alarm/error flags (`GENEL_ARIZA`, `PISTON_ILERI_GIDEMEDI`, `BASINC_ULASILAMADI`, etc.) with SCoil/RCoil.
- `"RECETE"`: Recipe parameters (`HEDEF_BASINC_BAR`, `BEKLEME_SURESI_SN`, `DONGU_HEDEF_SAYISI`, etc.).
- `"PARAMETRE"`: Persistent machine parameters (`MAX_GUVENLIK_BASINCI`, `POMPA_GECIKME`, etc.).
- `"ARIZA_ZAMANLARI"`: Timeout setpoints (`Time` type: `PISTON_ILERI_TIMEOUT := T#5s`).
- `"GECIKME_ZAMANLARI"`: Process delay setpoints (`Time` type: `BASINC_DUSURME_GECIKME := T#1s`).
- `"ANALOG"`: Sensor values (`Int` type: `ON_BASINC_MAX`, `ON_BASINC_OFSET`, `ON_BASINC_HAM`, `ON_BASINC_BAR`).
- `"PWM"`: Valve PWM tuning (`MIN_PWM_DEGERI`, `MAX_PWM_DEGERI`, `CALISMA_DUTY`).
- `"KOSULLAR"`: Motion condition interlocking bits (`PISTON_ILERI_KOSUL`, `PISTON_GERI_KOSUL`).
- `"SECENEKLER"`: System options and flags.

### 2. Standard `FC AI` and Main [OB1] Call Convention
- Dedicated function block `AI` (FC 1):
  - Interface: `AI` (Input, Int), `MAX` (Input, Int), `OFSET` (Input, Int), `POS` (Output, Int), `HAM` (InOut, Int), `REAL` (Temp, Real).
  - Logic: `NORM_X` (0..27648 $\to$ 0.0..1.0 Real) $\to$ `SCALE_X` (0.0..1.0 Real $\to$ 0..\#MAX Int $\to$ \#HAM) $\to$ `SUB` (\#HAM - \#OFSET $\to$ \#POS).
  - Main [OB1]: Dedicated network per sensor/ruler calling `AI` with its `ANALOG` DB variables before calling process blocks (`FC_Pistonlar`, `FC_OtoCycle`).

### 3. 2-Network Piston/Actuator Standard
Each motion consists of 2 consecutive Ladder networks:
- **Net 1 (Condition Interlock):** ONLY safety conditions:
  - `NOT "ERROR"."GENEL_ARIZA"` AND `Sensors` $\to$ `( ) "KOSULLAR"."PISTON_ILERI_KOSUL"`
- **Net 2 (Motion & Trigger):** Manuel and Oto triggers are placed **in parallel BEFORE the `KOSULLAR` contact**:
  - `Branch 1 (Manuel):` `"EL"` AND `"MANUEL_ILERI_BUTON"`
  - `Branch 2 (Otomatik):` `"OTO"` AND (`"OTO_W" == 5`)
  - Parallel join $\to$ `---[ ] "KOSULLAR"."PISTON_ILERI_KOSUL"---` $\to$ `( ) "PISTON_ILERI_VALF"`
  - Parallel to coil: `"TIMER"."TON_Piston_Ileri"` (PT: `"ARIZA_ZAMANLARI"."PISTON_ILERI_TIMEOUT"`).

### 4. Single-Network Cascaded PWM Standard
- In `FC_Pwm`, `NORM_X` $\to$ `SCALE_X` $\to$ `%QW...` PWM Out are cascaded in series on a single Ladder network (ENO $\to$ EN). Normalized ratio MUST be `Real`.

### 5. `OTO_W` Cycle Steps & Neutral Reset
- Step progression in `FC_OtoCycle` advances in steps of 5 (`0`, `5`, `10`, `15`...).
- In neutral position (`NOT "EL" AND NOT "OTO"`): `"OTO_W" := 0;` and all `"ERROR"` bits are reset (`RCoil`).

## Primary Communication Interfaces

### 1. Model Context Protocol (MCP)
Run the built-in MCP server:
```bash
python tiagent_mcp.py
```
Available tools:
- `tiagent_status`: Inspect TIA Portal connection, DBs, blocks, and compile logs.
- `tiagent_list_dbs`: List all DataBlocks (DBs) in the active project.
- `tiagent_get_project`: Get complete project overview (DBs, blocks, tag tables, tags).
- `tiagent_get_hardware`: Inspect all hardware devices, PLC racks, expansion slots, and plugged modules.
- `tiagent_add_module`: Plug an I/O or communication module into the PLC rack.
- `tiagent_import_package`: Import full package (LAD/SCL blocks, DBs, tags, hardware devices/modules).
- `tiagent_send_command`: Send natural language commands to TIA Portal.
- `tiagent_delete`: Delete blocks, tags, hardware.
- `tiagent_search_gsd`: Search GSDML catalog for drives and telegram modules.

### 2. HTTP REST Endpoints (Port 19520)
- `GET http://localhost:19520/api/status`
- `GET http://localhost:19520/api/dbs`
- `GET http://localhost:19520/api/project`
- `GET http://localhost:19520/api/hardware`
- `POST http://localhost:19520/api/package`
- `POST http://localhost:19520/api/command`
- `POST http://localhost:19520/api/delete`
- `GET http://localhost:19520/swagger.json`

### 3. File Hot-Folder (`Packages/Inbox` and `Packages/Outbox`)
For sandboxed or offline LLMs:
- Place package file in `Packages/Inbox/<id>.json`
- TIAgent automatically executes it and writes response to `Packages/Outbox/<id>.json.result.json`

## CLI Wrapper
You can execute terminal commands using:
```powershell
.\tiagent.ps1 status
.\tiagent.ps1 send <package.json>
.\tiagent.ps1 compile
```

## Data Type & SimaticML Rules
- **NORM_X / SCALE_X Data Types**: Normalized ratio variables (`*_Norm`) **MUST STRICTLY BE REAL** (`0.0 .. 1.0`), never `Int`. Feeding integer percentages (>1) to `SCALE_X` causes 16-bit integer overflow (>32767), setting `ENO=False` and dropping PWM/analog outputs.
- **TON Timer Pins**: Unconnected `ET` pins must be wired with `<OpenCon />`.
- **Binary Arithmetic**: Parts like `Sub` must not contain `<TemplateValue Name="Card">`.
